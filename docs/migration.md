# Extraction checkpoint

Source: `JTriggerFish/TriggerFish-VCV` at
`9f0d2e2ce0be3d51ff5e4ff45b0da5c2d7aaa621`.
The native application now owns percussion development. The obsolete Rack drum
shells, browser workbench, duplicate DSP/tests and browser-dependent fitting
scripts have been retired from the current VCV tree; this pinned revision
retains their history.

## Included

- Reusable percussion DSP, shared utility dependencies and 22 original C++ tests.
- Parameter descriptors/mapping, moved from the misleading `workbench/wasm`
  directory into `engine/parameters`; namespace/base-fit function renamed only.
- Six JSON factory sounds: crash, gong, ride, hi-hat, kick and snare.
  Calibration reference attachments and extra gong trials are local user presets,
  not distributable factory content. Their gestures and synthesis values were
  preserved, apart from the explicitly reviewed shared output-EQ conversion.
  A membrane/tom default is generated by the native patch registry; there was
  no standalone tom calibration JSON in the source set.
- Native JSON loading/validation, per-renderer owned state, a C API, direct NumPy
  rendering, explicit-coordinate fitting and selected existing numerical tools.
- Same development launcher conventions, uv environment, Git hooks and LF
  policy, plus native build/package/test CI for four OS/architecture runners.

No Rack modules, reverb/Rhodes implementations, browser UI, Node transport,
Wasm binaries, private recordings or generated render artifacts are included.

## Sound parity

A one-time migration check rendered the original workbench and this native
library at **44.1 and 48 kHz**, using all six stored fits and their saved events.
Each was rendered for six seconds, both as one strike and as five strikes at
0/0.5/1/1.5/2 seconds: **24 comparisons**. No level adjustment or limiter was used.
The old renderer was used only as the migration oracle, not as a new dependency.

Worst relative RMS difference: **0.0008752 (0.08752%)**, the repeated gong at
44.1 kHz. Its maximum absolute sample difference was **0.0003602**. Kick at
44.1 kHz was bit-identical; all remaining pairs were within that RMS bound.
These are numerical migration checks, not a new listening approval of the fits.
The local report and oracle renders are under ignored `build/parity/`.

### Repeatable regression checks

`tests/fixtures/migration-v1.json` preserves temporal and spectral RMS signatures
from those **legacy model outputs**, alongside the source commit, preset hashes
(LF-normalized) and full oracle PCM hashes. These are not private recordings.
The 24 cases run in the ordinary Python suite and CI. A 0.5% relative tolerance
plus a small floor allows cross-compiler rounding; absolute levels are retained.
These compact checks detect envelope/colour/gain regressions, but do not prove
sample-level or perceptual equivalence. Do not regenerate them from new output
merely to make a failing test pass.

Where the six-second legacy little-endian float32 files are available, reproduce
the full sample-by-sample comparison without Node or any legacy runtime:

```powershell
python -m drumfoundry.migration tests/fixtures/migration-v1.json presets/factory build/parity
```

The command verifies preset/oracle hashes and fails above 0.2% relative RMS. It
is read-only. This strict historical check now detects the intentional final-EQ
Q change from 0.8 to 0.7 in ride/hi-hat: roughly 0.22–0.31% relative RMS, rather
than a renderer regression. Accounting for that known filter change reduced the
ride discrepancy below 1e-7 and hi-hat below 0.03% in the pre-removal review.
The tolerance has **not** been widened, and no oracle was regenerated to hide
the difference. The compact temporal/spectral signature suite still passes.
Oracle filenames encode preset, rate and repeat flag; the committed
cases record these explicitly. Reacquiring or replacing an oracle requires the
pinned original renderer and an explicitly reviewed migration-baseline update.

At the initial extraction checkpoint, the 22 inherited native DSP tests and 66
Python tests passed on Windows/MinGW.
Tests include deterministic repeated rendering, arbitrary block partitioning,
more than four simultaneous voices, parallel independent voices, exact JSON
round-trip, rejected malformed patches and known-parameter fitting recovery.
Cross-platform execution is delegated to CI; do not claim it passed until it runs.

### Boundary review corrections

- Partial patches expand missing values into explicit stored C++ defaults;
  supplied values and fit/reference metadata are preserved.
- Decimal bounds use float-precision comparison, including fitter bounds. Enum
  values remain exact integers; Ring character is now correctly a choice.
- Native error state is updated consistently, with bounded storage and safe
  Unicode decoding in Python. Valid audio calls do not allocate error strings.
- WaveSpin is commit-pinned in the optional perceptual dependency group. Both
  published losses have separate executable smoke tests, including the renderer's
  floating-point sample-rate representation. Loss formulas are unchanged.
- Migration signatures and read-only full-PCM comparisons are now source-controlled.

Those initial corrections did not retune presets or modify DSP mathematics. Subsequent stages
added CLAP/standalone hosting and the shared native workbench, including editable
curves/modes, reference analysis, snapshots and hold-decay assistance; see
[native-ui.md](native-ui.md). Output EQ was subsequently simplified for all recipes.

## Fitting-tool migration

The current [native refinement workflow](refinement.md) retains structured-series
metal fitting, reference-floor Mel and bloom/texture/decay terms, kick ridge and
band-envelope losses, gong onset measurements, modulation/ridge diagnostics,
seed-separated audits and the component benchmark. Rendering, routing and event
ownership use the native API. The obsolete per-ridge stage list and one-time
reference importer have been removed. Historical design/experiment notes remain
at the pinned revision below rather than becoming competing current instructions.

Validation at removal includes native DSP and Python fitting tests on Windows/MinGW;
a real crash candidate was rendered, frozen, reloaded and independently audited.
This verifies the migration machinery, not a new calibration or listening result.
